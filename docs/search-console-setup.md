## Verify a custom domain

1. Open https://search.google.com/search-console and add a property.
2. Select Domain. Enter only the domain, without https:// or a path.
3. Copy Google's TXT verification value, normally google-site-verification= followed by your token.
4. In the authoritative DNS dashboard, add a TXT record at the domain root. Use the host/name syntax required by your DNS provider, usually @ or blank, and paste the exact value from Google. Add it alongside existing TXT records.
5. Return to Search Console and click Verify after the DNS record is visible. Retain the record after verification.

A Domain property covers protocols and subdomains. Google's exact steps: https://support.google.com/webmasters/answer/34592 and https://support.google.com/webmasters/answer/9008080.

## Verify a hosted subdomain or an exact URL

Use a URL-prefix property with the complete HTTPS origin when you cannot edit DNS for the host's domain. Choose HTML file or HTML tag verification. The project has no verification file or metadata token configured yet. If you choose a tag, provide the token Google gives you so it can be added to Next.js metadata; for file verification, provide Google's exact file and filename. A URL-prefix property covers only its specified protocol, host and path prefix.

## After the public URL and pages are decided

1. Configure canonical URLs and the final origin for metadata.
2. Create a sitemap of the canonical public URLs that actually serve indexable pages. Do not include gated desktop or admin pages.
3. Ensure robots.txt and the sitemap serve directly on the final domain.
4. Submit the actual sitemap URL in Search Console's Sitemaps report.
5. Use URL Inspection → Test live URL on the public landing page, inspect Google's rendered result, then request indexing.
6. Monitor Page indexing and Performance. Verification and sitemap submission do not guarantee indexing.

Sitemap guidance: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap.
URL Inspection guidance: https://developers.google.com/search/docs/monitor-debug/search-console-start.

## Your confirmed domain: dotm.in, DNS: GoDaddy, hosting: Vercel

1. In Search Console, add a **Domain** property and enter **dotm.in**.
2. Copy the exact **TXT** value from Google, beginning **google-site-verification=**.
3. In GoDaddy → Domain Portfolio → **dotm.in** → **DNS** → DNS Records → **Add New Record**:

   | Field | Value |
   | --- | --- |
   | Type | TXT |
   | Name / Host | @ |
   | Value | Paste Google's complete verification value |
   | TTL | GoDaddy's default is fine |

4. Save it alongside the existing records. Leave Vercel's A/CNAME and email records intact. If GoDaddy delegates the domain to another nameserver provider, add the TXT record at that authoritative provider instead.
5. Return to Search Console and click **Verify** once the TXT record has propagated. Keep it after verification. DNS verification needs no website deployment or Gmail password.
6. Once public pages and a sitemap are ready, submit the actual sitemap URL and use URL Inspection on **https://dotm.in/enter** (the current destination of the root redirect).

For an optional URL-prefix property **https://dotm.in/**, HTML-tag verification is now supported via the Vercel environment variable **GOOGLE_SITE_VERIFICATION**. Enter only the meta tag's content token, then redeploy. The Domain property via TXT is sufficient for domain-wide coverage.
